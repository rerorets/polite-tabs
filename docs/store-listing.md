# Chrome ウェブストアへの掲載

ストアの管理画面（デベロッパー ダッシュボード）に書き写す内容と、提出までの手順をまとめています。

## 提出までの流れ

管理画面の文言や並びは変わることがあります。見当たらない項目は近い名前のものを探してください。

### 1. デベロッパー登録（最初の 1 回だけ）

1. 公開に使う Google アカウントで 2 段階認証をオンにします。オフのままだと公開できません。
2. デベロッパー ダッシュボードを開きます。
   https://chrome.google.com/webstore/devconsole
3. デベロッパー契約に同意し、登録料を払います。限定公開でも登録料は要ります。
4. 「アカウント」の画面で、次の 3 つを埋めます。
   - **公開者の名前**：ストアで作者として出る名前です（例：rerorets）。
   - **連絡先のメールアドレス**：届いた確認メールのリンクを開くまで、提出できません。
   - **取引業者かどうかの申告**：EU の法律で求められる申告です。仕事として売り物にするのでなければ、「取引業者ではない」を選びます。

### 2. zip を作る

```sh
npm run package
```

リポジトリの直下に `polite-tabs.zip` ができます。中身は `build/` の中身です。

### 3. アイテムを作って埋める

1. ダッシュボードで「新しいアイテム」を押し、`polite-tabs.zip` をアップロードします。
2. 左のメニューの各タブを、この資料の内容で埋めます。

| タブ             | 書き写す節                                     |
| ---------------- | ---------------------------------------------- |
| ストアの掲載情報 | 下の「ストアの掲載情報」。画像もここで上げます |
| プライバシー     | 下の「プライバシー」                           |
| 配布             | 下の「配布」                                   |

### 4. 審査に出す

1. 右上の「審査のために送信」を押します。
2. 送信の画面で、審査に通ったらすぐ公開するかを選べます。自分の手で公開したいなら、自動で公開するチェックを外します。
3. 結果は連絡先のメールアドレスに届きます。通らなかったときは、理由がメールに書かれています。

> 補足：審査にかかる日数は決まっていません。`tabs` などの強い権限を使う拡張は、時間がかかりやすいです。

## ストアの掲載情報

### 名前

```
Polite Tabs
```

### 概要

manifest の `description`（132 文字まで）がそのまま使われます。元は `package.json` の `description` です。

```
URL やページのタイトルで、タブを自動でグループにまとめます。ほかの拡張が作ったグループには触りません。
```

### 説明

```
開いたタブを、あらかじめ決めたルールにしたがって、自動でタブグループにまとめます。

■ できること
・URL かページのタイトルで振り分けます。ワイルドカード（github.com など）と正規表現の 2 つの書き方が使えます。
・グループは、ルールの順にタブバーの左側へ並びます。
・グループをまとめて折りたたんだり、開いたりできます（Alt+Shift+C）。
・手動モードにすると、ショートカット（Alt+Shift+G）を押したときだけ振り分けます。
・ルールは一括編集で、テキストとしてまとめて書き換えられます。

■ ほかのグループには触りません
Polite Tabs が作っていないグループ（手で作ったものや、ほかの拡張が作ったもの）からは、タブを動かしません。AI のブラウザ操作などが作るグループとも一緒に使えます。

■ 細かな設定
・グループから外したタブを、元のグループに戻すかどうか
・ルールに当たらなくなったタブを、グループから外すかどうか
・タブが 1 枚だけのときはグループにしない
・ほかのグループを自動で折りたたむ
・折りたたんだグループにタブの数を出す

■ プライバシー
タブの URL とタイトルは、ルールに当たるかを調べるためだけに読みます。外部へは送りません。

ソースコード：https://github.com/rerorets/polite-tabs
Acid Tabs（MIT ライセンス）をもとに作っています。
```

### そのほかの項目

| 項目               | 入れる内容                                                           |
| ------------------ | -------------------------------------------------------------------- |
| カテゴリ           | 仕事効率化（ダッシュボードの選択肢から、いちばん近いものを選びます） |
| 言語               | 日本語                                                               |
| ホームページの URL | https://github.com/rerorets/polite-tabs                              |
| サポートの URL     | https://github.com/rerorets/polite-tabs/issues                       |

### 画像

| 画像                           | 大きさ   | 用意                                         |
| ------------------------------ | -------- | -------------------------------------------- |
| ストアのアイコン               | 128×128  | `src/public/icon-128.png` をそのまま使えます |
| スクリーンショット             | 1280×800 | `assets/store/screenshot-1.png`〜`-3.png`    |
| プロモーション用の小さいタイル | 440×280  | `assets/store/promo-small.png`               |

画像は `npm run store-images` で作り直せます。元のレイアウトは `assets/store/src` にあり、実際のポップアップと設定ページを、サンプルのルールが入った状態で埋め込んでいます。

## プライバシー

### 単一用途の説明

```
開いているタブを、利用者が決めたルール（URL やページのタイトルの条件）にしたがって、自動でタブグループにまとめることです。
```

### 権限の理由

| 権限            | 理由                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------- |
| `tabs`          | タブの URL とタイトルを読み、利用者のルールに当たるかを調べて、タブをグループに入れるため |
| `tabGroups`     | タブグループを作り、名前・色・並び・折りたたみを変えるため                                |
| `webNavigation` | タブの中でページが移ったことに気づき、移動先の URL ですぐ振り分け直すため                 |
| `storage`       | 利用者が作ったルールと設定を保存するため                                                  |

### リモートコード

「いいえ、リモートコードを使用していません」を選びます。拡張の中身はすべて zip に入っていて、外からスクリプトを読み込みません（絵文字の選択画面のデータも同梱しています）。

### データの使用

- 「ウェブ履歴」にチェックを入れます。タブの URL とタイトルを読むためです。
- 公式の FAQ では端末の中だけで扱うデータも申告の対象とされているので、外に送らないデータでも申告します。

次の 3 つの宣言にチェックを入れます。どれも、この拡張の今の作りに当てはまります。

- 承認されている用途以外で、ユーザーデータを第三者に販売、譲渡しない
- アイテムの単一用途と関係のない目的で、ユーザーデータを使用、譲渡しない
- 信用力の判断や融資の目的で、ユーザーデータを使用、譲渡しない

## 配布

| 項目     | 選ぶもの                                                         |
| -------- | ---------------------------------------------------------------- |
| 公開範囲 | 限定公開（リンクを知っている人だけが入れられ、検索には出ません） |
| 地域     | すべての地域                                                     |
| 料金     | 無料                                                             |

> 補足：あとから一般公開に切り替えられます。そのときは、この資料の内容のまま出せます。

## 更新するとき

1. `package.json` の `version` を上げます。ストアは前より大きいバージョンしか受け付けません。
2. `npm run package` で zip を作り直します。
3. ダッシュボードの「パッケージ」から、新しい zip をアップロードして、審査に出します。
